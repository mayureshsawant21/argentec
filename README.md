# Argentec — Corporate Website

Static corporate website for **Argentec**, a construction company in Mumbai (argentec.com).

Plain HTML, CSS and JavaScript. There's no build step, so it can be hosted directly on GitHub Pages.

## Expertise pages

The Expertise mega menu and the pages in `expertise/` are generated from
`scripts/expertise_content.py`. To change service content or the menu, edit that
file (or the template in `scripts/build_expertise.py`) and run:

```bash
python3 scripts/build_expertise.py
```

The script updates the Expertise menu in every root page (between
`<!-- expertise-menu -->` markers), rewrites `expertise/*.html` and refreshes
`docs/expertise-content-review.md`. It needs only Python 3, and the output is plain
HTML, so GitHub Pages needs no build step. Don't hand-edit generated pages.

**Before publishing**, go through `docs/expertise-content-review.md` with Argentec.
The BIM page carries `noindex` until its services are confirmed.

## Projects pages

Project data lives in `scripts/projects_data.py` (transcribed from the
October 2026 portfolio PDF). After editing statuses, run:

```bash
python3 scripts/build_expertise.py   # only if the header/menu changed
python3 scripts/build_projects.py
```

Images are neutral placeholders (`assets/img/projects/placeholder-1..4.svg`),
labelled "Representative image"; replace with real photography when available.

## Blog

Posts are written and published in the admin panel (**Blog**). The Markdown
files in `content/blog/` were the starting content and are only used by the
development build. To rebuild from them instead, run:

```bash
python3 scripts/build_blog.py
```

The sample article carries `noindex: true`; delete it (or replace its content)
before launch. Cover images go in `assets/img/blog/`.

## Two businesses (Phase 2)

- **Contracting** (everything except `development/`) uses white and silver, with
  navy as a small accent. Photographic heroes keep their dark overlay.
- **Development** uses blue as the primary colour with gold accents. Gold is not
  used anywhere else.
- The header carries a Contracting | Development switch (and the mobile menu
  repeats it). The home page has two entry panels just before the closing section.

Rebuild the Development page after editing its copy:

```bash
python3 scripts/build_development.py
```

Statements that need Argentec's confirmation are listed in
`docs/development-content-review.md`. Registrations of interest arrive in the
admin panel under **Enquiries → Development**.

## Vendors and Careers (Phase 3)

Content for both pages lives in `scripts/company_data.py`: material categories,
trade packages, registration steps, departments and open roles. After editing:

```bash
python3 scripts/build_company.py
```

Once the site is live, job postings are managed in the admin panel
(**Careers → Job postings**); the roles in `scripts/company_data.py` were the
starting content.

## Forms

Every form on the site (contact, careers with resume upload, vendor
registration, development interest) posts to `api/submit.php` through
`window.ArgentecForms` in `js/main.js`. Submissions are saved for the admin panel,
resumes are stored privately, and the visitor sees the reference number issued
by the server. A hidden honeypot field, a minimum fill time and a limit of 8
submissions per hour per connection keep spam out.

`contact.html?type=supplier|home|development` opens the form preselected;
`?type=careers` redirects to `careers.html`.

The forms need PHP, so they work on Hostinger, not on GitHub Pages or the
static preview.

## Admin panel

`https://argentec.com/admin/` — sign in with **admin** / **Argentec@123**, then
change the password under *My account* (a warning shows until you do).

| Section | What it does |
|---|---|
| Dashboard | New submissions per form, 30-day chart, applications by designation, latest submissions |
| Enquiries | Contact, vendor and development submissions: search, status, date range, notes, bulk actions, CSV export |
| Careers → Applications | Filter by designation, experience, status and date range (quick: today, 7 days, 30 days, this month); resume download and PDF view; status pipeline (new → shortlisted → interview → offered → hired / rejected); notes; CSV export |
| Careers → Job postings | Add, edit, duplicate, publish, close or delete roles; the openings, the form's role list, the team counts and Google Jobs data on careers.html update at once |
| Pages | Every heading, paragraph, list item, image, video and counter on every page, plus page title, search description, share image and "hide from search"; restore originals or earlier versions; site-wide footer |
| Blog | Write posts with a formatting toolbar, cover image, category, publish date, SEO fields; drafts and preview; publishing writes the blog pages |
| Media library | Upload and reuse images, videos and PDFs (also from the page and blog editors) |
| Tracking & SEO | Google Tag Manager, GA4, Meta Pixel, Microsoft Clarity, LinkedIn Insight, Search Console and Bing verification, custom head/body code; form submissions fire `form_submission` (dataLayer), `generate_lead` (GA4) and `Lead` / `SubmitApplication` (Pixel) |
| Settings | Website address, email notifications per form, health check, maintenance (rebuild website, re-apply page edits, sitemap, clean-up) |
| Users | Roles: Administrator, Content editor, HR / recruitment, Enquiries |
| Activity log, Backup | Who changed what; one-click zip of database, resumes, uploads and pages |

How it works: the admin panel writes changes straight into the static HTML
pages (keeping the previous version of each page), so the site stays fast and
search-friendly. Editable content is marked with `data-cms` attributes by
`scripts/cms_tags.py`, which the build scripts run automatically.

Data (SQLite database, resumes, backups) is kept in `argentec-private/` next to
`public_html`, where the web server cannot serve it. If that folder cannot be
created, `admin/data/` is used, which `.htaccess` blocks. Settings live in
`admin/inc/config.php`.

If a developer regenerates pages with the Python build scripts, open
*Settings → Maintenance* and click **Re-apply page edits** and **Rebuild website**.

## Deploy on Hostinger

1. In hPanel open **Files → File Manager → public_html**, delete the placeholder
   files, upload the website zip and **Extract** it into `public_html`.
2. Check **Advanced → PHP Configuration**: PHP 8.1 or newer, with the
   `pdo_sqlite`, `fileinfo` and `zip` extensions on (they are by default).
3. Open `https://argentec.com/admin/`, sign in and change the password.
4. In **Settings**, add the notification emails and send a test email. Create the
   mailbox `no-reply@argentec.com` (or change `mail_from` in `admin/inc/config.php`).
5. Turn on the free SSL certificate (hPanel → Security → SSL).

## Asset versions

CSS and JS links carry a content-hash version (`?v=…`) so browsers never use a
stale copy. The build scripts update it automatically; after editing CSS or JS by
hand, run `python3 scripts/cache_bust.py`.

## Preview locally

```bash
php -S localhost:8000      # site, forms and admin panel (needs PHP 8 with SQLite)
# open http://localhost:8000 and http://localhost:8000/admin/
```

`python3 -m http.server 8000` also serves the pages, but forms and the admin
panel need PHP.

## Deploy on GitHub Pages

1. Go to the repo on GitHub, then **Settings → Pages**.
2. Under **Build and deployment**, choose **Deploy from a branch**. Pick the branch and the `/ (root)` folder, then save.
3. The site will be live at `https://mayureshsawant21.github.io/argentec/`.

### Custom domain (argentec.com)

When the site is ready to go live:

1. In **Settings → Pages → Custom domain**, enter `argentec.com`. This commits a `CNAME` file.
2. At the domain registrar, add DNS records:
   - `A` records for `@`: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - `CNAME` record for `www`: `mayureshsawant21.github.io`
3. Turn on **Enforce HTTPS** once the certificate is issued.

## Re-encoding hero videos

The source clips were 1080p at about 13 MB each. They were compressed without audio for fast loading:

```bash
ffmpeg -i desktop.mp4 -an -c:v libx264 -preset slow -crf 29 -pix_fmt yuv420p -movflags +faststart assets/video/hero-desktop.mp4
ffmpeg -i mobile.mp4  -an -c:v libx264 -preset slow -crf 27 -vf scale=720:-2 -pix_fmt yuv420p -movflags +faststart assets/video/hero-mobile.mp4
```
